# test-case-design

一个用于设计软件测试用例的 Agent Skill。根据需求文档、UI 设计稿、接口文档，按一套定版的设计标准（v2）编写、补充和评审测试用例，适用于任何项目。

## 这套标准包含什么

- 14 个范围维度逐项必查，不适用的写明 N/A 理由
- 8 种设计方法综合使用：等价类划分、边界值分析、判定表法、因果图法、状态迁移法、场景法、正交实验法、错误推测法
- 5 类测试全覆盖：功能测试、性能测试、兼容性测试、易用性测试、安全测试
- 固定 14 个字段；编号 Test001 起、一个项目终身顺延，作废号登记进 `retired-ids.csv` 后不复用
- 优先级只设 P0 / P1 / P2，P0 不设比例上限，只按失败后果定级，每条 P0 在备注里写「P0 理由：」加四类后果之一（主流程不通、资金错误、权限穿透、状态错乱）；全套超过 30% 或单模块超过 50% 只告警复核
- 三方对齐：需求追溯矩阵写进测试分析说明，缺、冲突、模糊的点记进单独的待澄清文件
- 任务目录命名 `<项目名>-<任务名>-<yyyyMMdd-HHmmss>`，不带模块名；交付物为用例 CSV、同名 HTML 执行版、测试分析说明 md（含追溯矩阵）、待澄清 md
- 每个项目根目录有一份 `project-info.md`，记产品基线端、本次任务覆盖端和历史任务；任务启动时读取，缺失时在定项目那一步顺带收集基线端并按模板建出，交付时回写本次覆盖并追加一行历史
- 项目目录根下只放三样：任务目录、`retired-ids.csv`、`project-info.md`

## 文件

- `SKILL.md`：技能的流程与硬性规则
- `references/design-standard-v2.md`：设计标准全文（维度、方法、类型、字段、交付自查清单）
- `references/project-info-template.md`：项目信息文件 `project-info.md` 的模板
- `scripts/check_cases.py`：用例机械校验脚本（单个用例 CSV 或整个项目目录）
- `skill.yaml`：技能登记信息

## 安装

把整个 `test-case-design` 文件夹放进 Agent 宿主的技能目录即可（例如 Muse 的 `~/workspace/custom-skills/`），文件夹名保持 `test-case-design` 不变。

## 校验用例

用例数据文件（CSV，含全部 14 个字段）写好后运行：

```bash
python3 scripts/check_cases.py <用例文件.csv>   # 单个任务
python3 scripts/check_cases.py <项目目录>        # 项目全套
```

传项目目录时，脚本汇总每个任务目录现行版（版本号最大）的 `-用例-v<N>.csv`，并读 `retired-ids.csv` 核销跳号。

硬失败：编号格式错误或重号、核销后仍有跳号、优先级不合法、P0 备注缺「P0 理由：」或类别不合规、需求编号为空、步骤与期待结果行数不等、方法或类型用了非规范名称、执行方式不是 AI 执行或人工执行、人工执行备注为空、测试结果不在五个选项内、有模块没有错误推测法用例或只用一种方法；传项目目录时，8 种方法或 5 类测试未全覆盖也算硬失败（单个文件只告警）。

告警：P0 占比全套超过 30% 或单模块超过 50%；传项目目录时缺 `project-info.md`，或项目目录根下有任务目录、`retired-ids.csv`、`project-info.md` 以外的文件；对照测试分析说明里的需求追溯矩阵反查，未被用例覆盖的需求点、UI 元素、接口错误码（填「缺 UI 稿」「缺接口文档」的列跳过）。
